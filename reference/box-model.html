The box model

What width measures, and how to work out what lands on screen.

Four boxes, nested

BoxDefined by
contentthe content itself
paddingcontent + padding
borderpadding + border
marginborder + margin — space around, never part of the element's own size

The two sizing models

content-boxborder-box
Statusthe initial value — what you get by defaultopt-in, one line
width sizesthe content boxthe border box
Padding & borderadded outwardsubtracted inward
Screen widthwidth + padding + borderexactly width
Content widthexactly widthwidth − padding − border
Marginexcluded from both

The arithmetic

/* content-box (default) */
screen  = width + padding-left + padding-right + border-left + border-right
content = width

/* border-box */
screen  = width
content = width - padding-left - padding-right - border-left - border-right

Worked

width: 300px; padding: 20px; border: 2px solid;

  content-box  →  screen 344px,  content 300px    /* 300 + 40 + 4 */
  border-box   →  screen 300px,  content 256px    /* 300 - 40 - 4 */
The recurring trap

Remembering that border is added but forgetting that padding is too. Under content-box both are outside the declared width. A box that overflows its container by a suspiciously round number is almost always this.

Reading it instead of computing it

Devtools → Computed pane → the four-ring diagram at the top. Rings are content / padding / border / margin, innermost outward — the same four, same order. Hover a ring to highlight it on the page.
