What width actually measures

You were two numbers away. This lesson is about which two, and why they are the two that everyone loses.

Where you already were

Asked how wide this renders, you said 304px:

.card {
  width: 300px;
  padding: 20px;
  border: 2px solid black;
}

That answer is more right than a wrong answer usually is. You took the declared width, then added the border on both sides — 300 + 2 + 2. Which means you were not treating width as "the width of the thing on screen". You already had a model in which the box has layers and the declared number sits somewhere inside them.

The layer boundary was in the wrong place. The real answer is 344px, and the missing 40 is the padding.

The one idea

Under the default, width sizes the content box — the innermost layer. Both padding and border are added outside it. Not one of them. Both.

The four boxes

Every element the browser lays out is not one box but four, nested:

BoxWhat defines itIn the card above
Content boxwhere the content actually sits300px
Padding boxcontent box + padding300 + 20 + 20 = 340px
Border boxpadding box + border340 + 2 + 2 = 344px
Margin boxborder box + margin344px (no margin set)

The four names are web.dev's, and they are the names the browser devtools use too — worth adopting exactly, because it makes the devtools diagram readable without translation. web.dev — Learn CSS: Box Model

Why 344 and not 304

Because of a property you did not write, and whose value nobody chose:

box-sizing: content-box;   /* the initial value, per the CSS standard */

MDN states the consequence flatly: with content-box, the width and height properties "include the content, but do not include the padding, border, or margin." MDN — box-sizing

So width: 300px is not a promise about the element. It is a promise about the element's innermost layer, and everything you add after it grows the box outward.

The other model

One line moves the boundary to where you probably assumed it was:

.card {
  box-sizing: border-box;    /* width now measures the border box */
  width: 300px;
  padding: 20px;
  border: 2px solid black;
}

Now the card is 300px on screen. The padding and border are subtracted inward instead of added outward, so the content box shrinks to 300 − 40 − 4 = 256px. MDN: "include the content, padding, and border, but do not include the margin."

Same declaration, two values of box-sizing

content-box · width:300px
← 344px on screen →
border-box · width:300px
← 300px on screen →

These are real elements styled by the workspace stylesheet, not pictures of elements. Open devtools on this page and inspect them.

Stop guessing: read it instead

The mission says you should be able to fix a layout by reasoning about the box model rather than by trial and error. The instrument for that is the devtools box-model diagram, and this is the lesson to start using it on:

  1. Right-click either demo box above → Inspect.
  2. Find the Computed pane. At its top is a nested diagram with four rings — the same four boxes, in the same order.
  3. Read the numbers off the rings. One box reads 300 at the centre; the other reads 300 at the outside.

That diagram answers "why is this the size it is" faster than any amount of reading, and it is the habit Phase 1 exists to build.

Self-check — predict before you expand 
.thumb {
  box-sizing: border-box;
  width: 120px;
  padding: 8px;
  border: 4px solid;
}

How wide is it on screen, and how wide is its content box?

120px on screen. The content box is 120 − (2 × 8) − (2 × 4) = 96px.

Left open on purpose

If border-box is what you meant every time, the obvious move is to set it on everything, once. That is a real and common thing to do — and it is lesson 0002, not a footnote here. One win per lesson.
