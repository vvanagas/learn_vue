# Mission established: ship an app, not "learn Vue"

`2026-07-30`

The learner arrived with "I would like to learn vue" and immediately suspected
it was the wrong mission. It was — "learn Vue" names a tool, not an outcome,
which `MISSION-FORMAT.md` rules out for the same reason it rejects "get fitter".
Reframed to shipping a deployed application whose frontend they wrote, with the
CSS/layout weakness named as an explicit success criterion rather than left
implicit.

Four scope decisions were taken with the learner and now bind the plan:

1. **Outcome** — ship their own app end-to-end (not employability, not a work deliverable).
2. **Language** — TypeScript from the first line, matching existing typing instincts and letting `coding-rules` bind.
3. **CSS** — a dedicated foundations phase *before* any Vue, rather than routing around the weakness with a component library.
4. **Rigor** — `coding-rules` phases in at Phase 6, not lesson one.

**Implications:** decision 3 is the load-bearing one and will feel like a
detour from "learn Vue" for six weeks — expect to have to re-justify it, and
point back at the mission's third success line. Decision 1 remains incomplete:
the specific application is still unnamed, recorded as OWED in `MISSION.md`.
The plan holds without it through Phase 3; Phase 4 is blocked until it is
chosen, because "add a screen" needs a real screen to add.
